# 轻邮 v2 使用说明

## 本机受限试用：先读这几句

- **日常启动**：双击项目里的“启动轻邮.command”；页面显示真实邮箱模式，点击“连接 Gmail”后才能看同一账号的本地清单。启动或连接不会自动扫描、预览或退订。
- **先练习**：双击“体验演示.command”；页面必须显示“演示邮箱”，这里的邮件与回执全部是合成的。
- **操作顺序**：连接 → 主动扫描 → 给要保留的订阅加保护 → 选定对象并预览 → 检查对象与理由 → 明确确认 → 查看“操作记录”。已有“结果待确认”的对象不要重复提交，也不要为了试用撤销保护。
- **看懂结果**：“请求已接受”只表示对方返回接受回执；“结果待确认”表示可能已发出但无法确认，不应重复提交；“需要人工处理”表示程序没有可靠自动方式，需要本人查看原邮件。
- **安全退出**：关闭弹窗不停止任务。需要停止时使用任务里的停止按钮，等它结束，再回启动终端按 **Control+C**，等终端命令结束。关闭浏览器页也不会关闭服务。退出后可再次双击启动；端口可能变化，用本次终端给出的地址。
- **第二次启动提示已有实例**：回原来的终端/页面，不删除 `app.lock`，不强行关闭来历不明的进程。程序按数据目录限制一个实例，演示与真实模式默认分目录。

启动器优先用项目 `.venv-v2-p5`，其次为原 `.venv-v2`；不自动使用旧 `venv` 或系统 Python。`environment_missing` 表示缺项目环境，`environment_incomplete` 表示环境不完整，`startup_failed` 表示目录或端口等启动问题；请按下方重建说明或检查终端提示。终端新增诊断为英文安全错误码。

**验证限制**：隔离合成数据已用于检查脚本启动、退出、重启、数据库恢复与浏览器界面。Finder 双击及 macOS 安全弹窗尚未完成独立验收，命令行脚本测试不能代替它们。运行中的旧实例需正常退出后再次启动，才会加载更新的代码。

## 重建环境

已经能正常使用时无需重装。以下步骤在项目里新建隔离环境，按固定版本安装依赖，不修改系统 Python 或旧环境。依赖重建曾在 macOS arm64、Python 3.14.4 上验证；其他组合需要自行核对。

首次安装时，在项目目录的终端依次执行：

```bash
python3 -m venv .venv-v2
.venv-v2/bin/python -m pip install -r requirements-v2.lock
.venv-v2/bin/python -m pip check
```

运行依赖锁定在 `requirements-v2.lock`；只有开发测试才需安装 `requirements-v2-test.lock`。完整步骤及适用范围见 `docs/V2_REBUILD.md`。已有项目环境时不要覆盖；本项目不会替你安装系统 Python。

## 数据在哪里、怎样备份和恢复

默认真实数据在项目 `.local/v2-live/`，演示数据在 `.local/v2-demo/`；用过 `--data-dir` 时以指定目录为准。`workspace.sqlite3` 保存清单、保护、核验状态、计划和执行历史；`token.json` 是登录凭据，`verification-traces/` 是匿名核验记录。`.local` 是隐藏目录，可在 Finder 用“前往文件夹”输入完整路径。

1. 先停止未开始任务，等待在途任务结束，在启动终端按 Control+C 并等命令结束；确认使用同一目录的实例都已退出。
2. 将**整个对应数据目录**复制到自己保管的本机加密位置，注明备份时间；其中可能含凭据与邮件资料，不发给他人、不放公开仓库或共享云盘。项目根目录 `credentials.json` 是另一个敏感文件，需要时单独妥善保管。
3. 恢复时保持服务关闭，把备份复制到一个**新目录**，保留原目录；先用同一交付版本和 `--data-dir` 指向该目录启动。真实模式需要连接同一账号才看到对应清单。恢复到新目录不等于创建了新的退订额度。
4. **旧备份不能撤回已发送请求**。若备份之后有真实提交，它可能缺少去重历史；此时不要预览或确认退订，保留最新原目录并先核对记录。不要同时使用新旧副本执行同一个订阅。

仅“退出后复制合成目录，再打开恢复副本”经过本轮测试；真实凭据恢复、跨电脑恢复、降级旧代码均未测试。没有一键备份/恢复按钮，不自动迁移真实库。结果待确认在刷新、重启和重新预览后仍应保留，不能清除状态来重发。

## 打开应用

在 macOS 中双击项目里的 **启动轻邮.command**：终端会启动本机应用并尝试打开浏览器。若没有自动打开，请复制终端里本次显示的本机网址；提示已有实例时回到原实例。应用启动后仍未读取你的邮箱；点击“连接 Gmail”才开始 Google 授权。

想先体验操作，双击 **体验演示.command**。页面会明确标注“演示邮箱”，其中所有邮件、数字和执行回执都是合成数据，不会发出真实退订请求。

终端等价命令：

```bash
python3 app.py --demo
.venv-v2/bin/python app.py --live
```

没有虚拟环境时先按本文“重建环境”操作。`Control+C` 关闭本机服务。它没有后台常驻、自启动或定时任务。

## 真实邮箱准备

1. 在 Google Cloud Console 中启用 Gmail API，创建桌面应用 OAuth 客户端，把文件保存为项目根目录的 `credentials.json`。
2. 使用本文“重建环境”的锁定依赖，不在旧环境或系统 Python 安装。
3. 打开真实邮箱模式，在界面中点击连接，完成 Google 的只读授权。

新版令牌写在 `.local/v2-live/token.json`，不自动读取旧版根目录的 `token.json`。只读权限可以扫描与验证原始邮件，不能通过 Gmail API 发信、删除邮件或归档。Google OAuth 界面及账号政策以现场实际结果为准。

## 整理流程

1. **扫描**：先扫描最近30天的促销邮件，默认上限100封，可调整到最多2000封。扫描可停止；达到上限或网络部分失败会保留已有结果并标记不完整。
2. **审阅**：搜索订阅、查看样本主题和处理理由。银行、Google与敏感邮件会受到保护或提示保留；建议不是对邮件重要性的保证。
3. **保护**：对想保留的域名添加保护，后续预览和执行立即采用新的规则。
4. **预览**：最多选择20个订阅。预览会列明可以提交、需要人工处理与被保护阻止的项目。真实模式此时按需获取所选原始邮件并验签。
5. **确认**：只有明确确认计划才提交请求，五分钟未执行的计划需要重新预览。结果逐项保留。

“请求已接受”指服务器回执，不能保证对方永远不发邮件；“不确定”表示连接中断等情况导致结果无法确认，此时不会自动重复提交。缺少可靠的一键方式时打开 Gmail 邮件人工处理，不让程序猜测网页按钮。

每个订阅的详情都保留 Gmail 原邮件入口，已验签或已保护的项目也可以查看。打开后可能需要你本人登录或选择账号；只有确认进入正确账号的对应邮件，才算定位成功。查看原邮件不会替你点击发件方退订链接。

## 隐私与限制

- 数据保存在本机，前端不加载远程字体、统计脚本或广告。
- 不使用付费AI，不把邮件发送给模型提供商。
- 不扫描真实邮箱之外的旧环境、插件或后台服务。
- 退订请求需要连接邮件发送方的公开网站，也可能让对方知道地址仍在使用；只选择你认识并愿意退订的列表。
- 没有安装 dkimpy、邮件验签失败或旧邮件签名无法验证时，只提供人工入口，不强行自动执行。
- 目前不迁移旧版“成功退订”记录，不提供邮箱删除与自动归档。

## 故障排查

网页出现“Load failed”时，先看启动终端是否仍在运行，并使用终端本次显示的网址；关闭终端会停止本机服务。已有一次服务退出的具体原因尚未查明，不能仅凭这个提示判断扫描失败。连接失败先检查客户端凭据、Google授权配置和网络；界面错误不包含令牌。扫描中途失败时已有订阅仍保留，可缩小上限后重试。不会通过更改系统代理、绕过macOS安全设置或扩大Gmail权限来自动修复。

旧版 `scan` / `unsubscribe --confirm` 命令不再是受支持入口；`python main.py` 现在也打开v2。根目录旧模块和旧文档保留用于历史对照，不代表新版架构。

## P1 补充：连接、任务与恢复

首次准备：在 Google Cloud 创建项目并启用 Gmail API，配置 OAuth 同意屏幕；若项目处于测试模式，把自己的邮箱加入测试用户。创建“桌面应用”类型的 OAuth 客户端并下载 JSON，放到页面显示的路径，或启动时用 `--credentials /你的路径/客户端.json` 指定。页面“文件存在”只说明找到文件；“格式已检查”只说明 JSON 结构有效；账号显示“已连接”才表示授权成功。

连接失败可重试：缺文件就补文件，格式错误重新下载桌面客户端 JSON，授权未完成回 Google 页面完成；网络失败检查网络后重试。令牌失效或权限不符且重复连接仍失败时，先关闭应用，在 Finder 中打开本应用数据目录，将 **该目录中的 token.json 移到自己保管的备份位置**，再启动并重新授权。默认真实目录是项目 `.local/v2-live/`；使用过 `--data-dir` 时以自己指定的目录为准。不要移动整个数据库目录，不要处理旧版根目录的令牌，也不要把令牌内容发给他人。本轮实现没有替你移动任何真实文件。

尚未验签的一键候选显示“待核验”，可以选择审阅；核验中、已验证、无法验证、无自动方式分别显示在列表或详情中。只看见候选不会发送请求，验签通过后仍需你确认计划。每批最多20项，超限全选会明确拒绝。

核验与提交在后台逐项运行；关闭弹窗只隐藏它，可用“查看任务”重开。退出时先停止未开始项并等待任务结束，再在启动终端按 Control+C；程序会等待在途操作并关闭数据库。不要把关闭浏览器页当作退出服务。刷新页面只查询任务，不重新提交。“停止未开始项”不能撤回已发送请求：核验会等待当前读取结束且不生成未完成计划；执行会保留在途项回执，结果不确定时不自动重发。普通HTTP读取单次20秒，可能有最多3次读取尝试；Google授权等待180秒。界面“正在停止”表示当前调用仍在等待结束。

扫描摘要显示时间、范围、读取、已保存、新增、跳过、读取失败和重复数量。零结果不扩大范围；达到上限、取消、部分失败、网络中断分别说明。每20封或页尾以事务保存，写入失败回滚当前批次，之前已提交的数据保留。重启后连接同一账号可见“上次扫描中断”和已保存数；不会自动重扫，必须由你主动再次扫描。

已有 v2 库无需手动迁移：新增状态存于原有 JSON，缺失字段保守读取；保护和操作历史保留。重启遗留 pending 仍为不确定，不因重新预览而重发。有限范围的真实试用不能证明所有邮件都支持自动处理，也不能证明对方已经停止发信。

## 核验记录

真实模式每条所选代表邮件的预览，会在当前数据目录的 `verification-traces/` 保存一个匿名记录文件。记录包括 UTC 起止时间、metadata/raw 读取尝试、DKIM 签名检查及 DNS 回调的结果；不记录邮箱地址、邮件标识、主题、正文、退订 URL、DNS 查询名或答案。文件仅当前用户可读写。写入失败会停止预览，不生成可提交计划。

记录中的尝试数是应用调用 SDK 的次数（SDK 自动重试设为 0），DNS 次数是验签库调用解析函数的次数，均不等同于网络包数；底层令牌刷新和 DNS 解析器内部重试未被逐次观测。旧版本没有采集的历史记录不会补写。
